# Data Model & Schemas

## Purpose
Document all data entities, their relationships, storage strategy, and migration approach used across the platform.

---

## Storage Overview

The system uses **three data stores**, each with a distinct purpose:

- **IdentityContext** — MySQL (EF Core + ASP.NET Identity), database `arenaraid-users`. Stores user accounts, roles, and auth tokens.
- **DataModelContext** — MySQL (EF Core), database `arenaraid`. Stores arenas, memberships, friendships, friend requests, and user profiles.
- **Redis** — StackExchange.Redis. Transient session state only: online users, active connections, live arena instances.
- **DataProtectionKeysContext** — MySQL database `arenaraid-protkeys`. Stores ASP.NET Data Protection keys for encryption.

## Persistent Entities (MySQL)

### User
> Table: `AspNetUsers` (managed by ASP.NET Identity) — Context: `IdentityContext`

Extends `IdentityUser`, which provides built-in fields like `PasswordHash`, `SecurityStamp`, `ConcurrencyStamp`, etc.

```
Id            string   GUID, auto-generated by Identity
UserName      string   3–20 chars
Email         string   6–50 chars
PasswordHash  string   managed by Identity
PhoneNumber   string   max 12 chars
FirstName     string
LastName      string
DOB           DateTime
Created       DateTime
LastLogin     DateTime
```

**Relationships:**
- Owns one `UserProfile` via `UserId` FK
- Referenced by `Friendship`, `FriendRequest`, `ArenaMember`

---

### UserProfile
> Table: `UserProfiles` — Context: `DataModelContext`

```
UserId    string   PK, FK --> AspNetUsers.Id — one-to-one with User
Bio       string?  optional, max 200 chars
Pronouns  string?  optional, max 50 chars
AvatarId  int      default: 1, range 1–16 - pre-set avatars that are mapped in the frontend
```

---

### ArenaConfiguration
> Table: `Arenas` - Context: `DataModelContext`

Represents a persistent lobby or room definition. Top-level lobbies have no parent; rooms have a `ParentGuid` pointing to their lobby.

```
Guid         string   PK
ParentGuid   string?  FK --> Arenas.Guid
Name         string
Description  string
MOTD         string   stands for message of the day
Password     string   empty string = unprotected
ImageUrl     string   banner/thumbnail URL
OwnerId      string
IsOfficial   bool
IsPublic     bool     true = visible in listings
IsStatic     bool     if true, persisted to DB
HasVoice     bool
HasVideo     bool
HasImages    bool
CreatedAt    DateTime default: UtcNow
```

**Relationships:**
- Self-referencing: one lobby --> many child rooms
- Has many `ArenaMember` entries

---

### ArenaMember
> Table: `ArenaMembers` - Context: `DataModelContext`

Composite PK on `(ArenaGuid, UserId)`

```
ArenaGuid  string   PK, FK --> Arenas.Guid
UserId     string
Role       string   values: "member", "admin"
```

---

### Friendship
> Table: `Friendships` - Context: `DataModelContext`

Composite PK on `(UserId, FriendId)`

```
UserId     string
FriendId   string
GroupName  string?
Created    DateTime   default: UtcNow
```

---

### FriendRequest
> Table: `FriendRequests` - Context: `DataModelContext`

Composite PK on `(FromUserId, ToUserId)`

```
FromUserId  string   PK - sender
ToUserId    string   PK - recipient
Comment     string?  optional message **not yet implemented** 
Created     DateTime default: UtcNow
```

## Redis Entities

These models exist only while users are connected and are not written to MySQL.

### HubUser
Session state for a connected user.

```
UserId         string
UserName       string
UserNameSlug   string        lowercase no spaces
PortraitId     int
UserNameColor  string
FrameId        int
ArenaGuid      string        GUID of current arena
SpamCount      int
LastMessage    DateTime 
Status         OnlineStatus
```

---

### HubConnection
Represents a single SignalR connection. A user may have multiple active connections (multiple tabs/devices).

```
ConnectionId  string  SignalR connection ID
UserId        string  identity user ID
UserName      string  lowercase slug
IPAddress     string  client IP or X-Forwarded-For value
UserAgent     string  browser user-agent string
```

## Migrations Strategy

- **Tool:** Entity Framework Core, code-first with `dotnet ef migrations`
- **Provider:** `UseMySql` with `ServerVersion.AutoDetect`
- **Approach:** Schema changes to `DataModelContext` are managed through explicit migration files. `Database.EnsureCreated()` is still called on startup as a fallback, but incremental changes are applied via migrations.
- Identity tables like `AspNetUsers` and `AspNetRoles` are managed entirely by ASP.NET Identity and should not be modified manually.
